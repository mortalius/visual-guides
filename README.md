# Visual guides

Интерактивные визуальные гайды по инфраструктурным темам. Каждый гайд - самодостаточная
статическая страница: без сборки, без фреймворков, без зависимостей кроме Google Fonts.
Общий визуальный язык - тема «Blueprint Journal» (инженерный журнал / чертёж): цвет несёт
смысл роли элемента, а не украшает.

## Гайды

| Гайд | О чём | Что читатель понимает |
|------|-------|----------------------|
| [`envoy-gateway-visualization/`](envoy-gateway-visualization/) | **Envoy Gateway и Gateway API**: связи между CRD, путь трафика по шагам, точки применения политик, режимы развёртывания и миграция с Ingress. | **Топологию**: кто на кого ссылается и какое поле на что влияет |
| [`traces-tempo/`](traces-tempo/) | **Путь трейса**: head sampling, `tail_sampling`, лимиты ingestion Tempo, границы блоков, чтение и производные данные. | **Количество**: сколько трейсов доедет, где теряется, чем лечится |

## Запуск локально

**Http-сервер обязателен.** Гайды подгружают части через `fetch`, а он блокируется на
`file://` политикой CORS - при открытии файла напрямую страница останется пустой.

```bash
cd <папка гайда>
python3 -m http.server
# → http://localhost:8000
```

Добавьте `?selftest=1` к URL, чтобы прогнать внутренние проверки гайда.

## Документация

| Документ | О чём |
|----------|-------|
| [`DESIGN.md`](DESIGN.md) | **Закон серии**: палитра, типографика, базовые компоненты, обязательный минимум страницы, реестр отклонений. Общий для всех гайдов. |
| [`CONTRIBUTING.md`](CONTRIBUTING.md) | **Процесс**: структура папки гайда, обязательная структура README, self-test, чек-лист публикации, деплой. |
| `<гайд>/README.md` | Представление конкретного гайда: файлы, навигация, контракты, типовые правки. |
| `<гайд>/DESIGN.md` | Локальная надстройка: свои компоненты и отклонения от закона с причинами. |

Разделение осознанное: общее - в корне, специфика - в гайде, дублирования нет. Копия
документации расходится с оригиналом так же незаметно, как копия кода.

## Проверка соответствия закону

Токены копируются в каждый гайд физически - гайд остаётся самодостаточным и деплоится как
отдельный сайт. Синхронность обеспечивает не доверие, а скрипт:

```bash
node tools/check-tokens.mjs                 # все гайды
node tools/check-tokens.mjs <папка гайда>   # один
```

Эталон читается из блоков `<!-- canonical:... -->` в `DESIGN.md`, поэтому живёт ровно в одном
месте. Скрипт проверяет: значения базовых токенов, покрытие семантических ролей, правило
брендового акцента и то, что все ссылки вида `DESIGN.md §3.7` из кода ведут в существующие
разделы. Код возврата 1 при расхождениях - пригоден для CI.

## Публикация

Каждый гайд - отдельный статический сайт на Render, конфигурация в
[`render.yaml`](render.yaml). Чек-лист перед публикацией - `CONTRIBUTING.md` §6.

## Структура

```
DESIGN.md            закон визуального языка
CONTRIBUTING.md      как создавать и вести гайды
render.yaml          блюпринт: по сайту на гайд
tools/               скрипты проверки
<guide-name>/        гайд: index.html, styles.css, data.js, app.js, README.md, DESIGN.md
```

## Лицензия

Образовательные материалы. Все примеры манифестов и конфигов - синтетические, с абстрактными
значениями, не привязаны к какой-либо конкретной инсталляции.
