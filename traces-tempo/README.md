# Путь трейса: обработка, фильтры и семплинг - представление и правки

Путь трейса от SDK до объектного хранилища: head sampling, `tail_sampling`, лимиты ingestion
Tempo, границы блоков, чтение и производные данные. Читатель уходит с пониманием
**количества**: сколько трейсов доедет, где и сколько теряется, каким параметром это лечится.
Каждый механизм документирован по отдельности - здесь они собраны в один путь с
количественными последствиями на каждом шаге.

Запуск: `python3 -m http.server` в этой папке → `http://localhost:8000`.
Артефакт статический и хостится на вебсервере.

Этот документ - про **представление** (что из чего состоит, где что менять). Визуальный
язык - в [`DESIGN.md`](DESIGN.md) и [корневом `DESIGN.md`](../DESIGN.md); расчётная модель -
в `model.js`; процесс и чек-листы - в [`CONTRIBUTING.md`](../CONTRIBUTING.md).

## Файлы и зона ответственности

| Файл | Что содержит | Когда править |
|------|--------------|---------------|
| `index.html` | **Оболочка**: шапка, пустые контейнеры навигации, доска, боковая панель, футер. Разметки схем нет - всё рисуется из JS. | Изменить шапку, футер, порядок подключения ассетов. |
| `model.js` | **Расчётное ядро**: чистые функции без DOM (`resolve`, `collectorFunnel`, `tempoFunnel`, `blockSlicing`, `readPath`, `widthOf`, `fmtPct`). Единственный источник цифр для всех линз. | Менять математику семплинга/лимитов, шкалу ширины, формат чисел. |
| `data.js` | **Контент-модель**: `ACTS`, `LENSES`, `MATRIX`, `COPY`, `ROLES`, `KNOBS`, `CONFIGS`, `LOSS_POINTS`, `VERSIONS`. Чистые данные. | Изменить любой текст, состав ручек, фрагменты конфигов, точки Атласа потерь. **Большинство правок - здесь.** |
| `app.js` | **Поведение и рендер линз**: `STATE`, навигация, 13 функций-рендереров, self-test. | Добавить/изменить саму схему линзы, логику взаимодействия. |
| `styles.css` | **Стиль**: токены темы «Blueprint Journal» + компоненты (см. `DESIGN.md`). | Цвета, отступы, типографика. |

**Порядок загрузки** (низ `index.html`): `model.js` → `data.js` → `app.js`. `app.js` вешает
обработчики и рисует при загрузке, поэтому подключается последним. Ассеты идут с `?v=N` -
**при правке бампайте версию** во всех четырёх тегах и в `<link>` на `styles.css`, иначе
браузер отдаст старый файл.

## Навигация

Три уровня:

- **Акт** (карточка-таб) - где мы на пути: `birth` → `collector` → `tempo` → `read`.
  У каждого свой оттенок; он же задаёт `--act-hue` для второго уровня и полосы доски.
- **Линза** (пилюля) - под каким углом смотрим. Пять линз **переиспользуются** между актами.
- **Ручки** (боковая панель) - параметры; пересчитывают все линзы согласованно.

| Линза | Акт 1 Рождение | Акт 2 Коллектор | Акт 3 Tempo write | Акт 4 Чтение |
|-------|:--:|:--:|:--:|:--:|
| **Карта пути** | ✓ | ✓ | ✓ | ✓ |
| **Воронка объёмов** | ✓ | ✓ | ✓ | ✗ объём не сужается |
| **Таймлайн** | ✗ решение мгновенное | ✓ | ✓ | ✓ |
| **Резолвер политик** | ✗ политик ещё нет | ✓ | ✗ лимиты, не голосование | ✗ |
| **Шардирование** | ✗ один процесс | ✓ сломанный LB | ✓ hash ring | ✗ |

Ось «Шардирование» намеренно живёт в актах 2 и 3 как контраст: одна задача (локальность
trace ID), решённая вручную и системно.

## Ключевой контракт

**Матрица акт × линза.** `MATRIX[act][lens]` в `data.js`: `true` - линза живая, **строка** -
причина, почему погашена. Погашенная линза остаётся видимой и объясняет причину в
`title`/`aria-description`: читатель узнаёт не только что смотреть, но и почему здесь нечего.
Живых комбинаций **13 из 20**.

**Инвариант:** каждая живая комбинация обязана иметь и рендерер в `RENDERERS` (`app.js`), и
запись в `COPY` (`data.js`). Проверяется self-test'ом - в отличие от остальной серии, здесь
рассинхрон не может уехать в прод незамеченным.

**Второй контракт: `STATE.params` ↔ `KNOBS`.** У каждого ключа параметра обязано быть
описание в `KNOBS`, иначе ручка не отрисуется. Проверяется self-test'ом.

**Третий контракт: `{{ключ}}` в `CONFIGS` ↔ `STATE.params`.** Плейсхолдеры в фрагментах
конфигов подставляются из состояния - незнакомый ключ останется в тексте как есть.

## Сквозные фичи

- **Легенда цветов** (`rolesLegend`, `edgeLegend`) - рисуется из `ROLES`, соответствие
  «цвет → роль узла»; «цвет → акт» несут сами табы.
- **Числа как контент**: все проценты и значения - моно + `tabular-nums`, разрядность из
  `fmtPct` в `model.js`. Подписи не должны дёргаться при движении ползунка.
- **Self-test** (`?selftest=1`) - 36 проверок расчётной модели и вёрстки. Единственная защита
  количественного материала от тихого расхождения цифр между линзами.
- **Погашенные линзы** - видимы, с причиной в `title` (см. `DESIGN.md` §3.13).
- **Адаптив**: `.diagram-scroll` с `overflow-x:auto` + `min-width` на `svg`; на ≤680px табы
  в колонку, панель вниз.
- **Кэш-бастинг**: `?v=N` в четырёх тегах ассетов + `<link>` на `styles.css`. Держите
  синхронными.

## Как выполнить типовые правки

### Изменить текст линзы

Только `data.js` → `COPY['<act>/<lens>']`: `title`, `hint` (мелкая подпись справа от
заголовка), `lede` (вводный абзац). HTML разрешён (`<code>`, `<b>`). Выводы под схемой
(`.note`) живут в рендерере в `app.js` - там они переплетены с числами из модели.

### Добавить/изменить ручку

1. `app.js` → `STATE.params` - добавить ключ со значением по умолчанию.
2. `data.js` → `KNOBS` - `label`, `min`, `max`, опц. `step`/`unit`/`code`/`hint`.
   `hint` должен называть **реальный параметр** конфига - иначе интерактив не переносится на
   эксплуатацию.
3. В нужном рендерере вызвать `knobsSection(side, ['ключ', ...])`.

Self-test проверяет, что у каждого ключа из `STATE.params` есть описание в `KNOBS`.

### Изменить фрагмент конфига

`data.js` → `CONFIGS`. Плейсхолдер `{{ключ}}` подставляется из `STATE.params`, поэтому конфиг
показывает **текущее положение ручек**. Подсветка ключей/значений/комментариев -
автоматическая (`configSection` в `app.js`). Значения держите абстрактными и круглыми:
артефакт вендор-нейтрален.

### Добавить линзу в акт

1. `data.js` → `MATRIX[act][lens] = true` (вместо строки-причины).
2. `data.js` → `COPY['<act>/<lens>']` - заголовок, hint, лид.
3. `app.js` → функция-рендерер `(board, side)` и запись в `RENDERERS`.

Пока рендерера нет, `render()` показывает плейсхолдер - страница не ломается.

### Рисование схемы: помощники в `app.js`

- `svgRoot(w, h, label)` + `mount(board, svg)` - обёртка с горизонтальным скроллом.
- `node(g, {x, y, w, h, kind, title, sub, hue, cls, cost})` - узел. `hue` - **категорийный**
  токен роли (`--c-*`), не семантический. `cls`: `keep`/`drop`/`warn` (судьба), `control`
  (пунктир, не основной поток), `stateful` (держит буфер; `cost` - подпись цены).
- `edge(g, d, {cls, label, lx, ly})` / `hline(...)` - связь «куда идёт». Толщина постоянна.
- `ribbon(g, x0, y0, w0, x1, y1, w1, cls)` - поток «сколько идёт». Нулевой поток не рисуется.
- `widthOf(value, total)` - нелинейная шкала ширины (γ=0.5). **У каждой ленты обязательна
  подпись процентом** (`.n-pct`): после γ-сжатия ширины непропорциональны.
- Панель: `sect`, `html`, `knobsSection`, `configSection`, `rolesLegend`, `edgeLegend`.

## Проверка после правок

1. `python3 -m http.server` → открыть страницу.
2. **`?selftest=1`** - баннер с проверками расчётной модели. Должно быть **36/36 passed**.
   Покрывает: балансы потоков во всех воронках, вето `drop`, `max(p)` vs `1-Π(1-p)`, нарезку
   блоков, асимметрию чтения, монотонность и нелинейность шкалы ширины, формат чисел, 13 живых
   комбинаций (рендерер + текст + рендер без исключений) и **переполнение подписей**
   (`getComputedTextLength()` по каждому узлу и по `viewBox`).
3. Проклацать все четыре акта и все линзы; консоль без ошибок (кроме `favicon.ico` 404).
4. Подвигать ручки: числа меняются согласованно, подписи не дёргаются по горизонтали.
5. Проверить выбранную кнопку линзы **под курсором**: `:hover` не должен перебивать
   `[aria-selected="true"]` (эта ошибка уже была - см. `DESIGN.md` §3.13).
6. Узкий экран (≤680px): табы в колонку, панель уходит вниз, схема со своим скроллом.
7. `node ../tools/check-tokens.mjs traces-tempo` из корня репы - без расхождений.

> **Переполнение подписей - главная ловушка этого артефакта.** SVG не переносит текст, поэтому
> длинная подпись молча вылезает за рамку узла. Не полагайтесь на глаз: правьте текст - и
> прогоняйте `?selftest=1`.

Общий чек-лист перед публикацией - в [`CONTRIBUTING.md`](../CONTRIBUTING.md) §6.

## Отклонения и открытые вопросы

**Отклонения от общего закона** - в [`DESIGN.md`](DESIGN.md) §5. Кратко: `.eyebrow` в indigo
(rose занята семантикой потери), боковая панель - пульт линзы без пустого состояния, введён
модификатор узла `.node.stateful`.

**Статус наполнения:**

| Что | Статус |
|-----|--------|
| Каркас, тема, расчётное ядро, self-test | ✅ |
| Акт 2 - коллектор, все пять линз | ✅ |
| Акт 3 - Tempo write path, четыре линзы | ✅ |
| Акты 1 и 4 | ✅ |
| Оверлей «Атлас потерь» (данные готовы в `LOSS_POINTS`, UI - нет) | ⏳ |
| Шесть сценариев-пресетов | ⏳ |

**Открытые вопросы:**

- **Нет OG-тегов и favicon** - блокер для публикации (то же, что у `envoy-gateway-visualization`).
- **Числа иллюстративные.** Модель считает согласованно, но входные доли когорт - оценочные;
  дисклеймер живёт рядом с ручками (`DESIGN.md` §3.11) и убирать его нельзя.
- **Внутренний технический бриф не опубликован** (`.gitignore`): содержал ссылки на приватные
  репозитории и имена кластеров. Обоснования решений, которые в нём были, переехали в этот
  README и в `DESIGN.md`; при необходимости восстанавливать - из локальной копии.
