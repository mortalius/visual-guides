HTTPRoute участвует дважды (бирюзовые карточки): сначала Envoy резолвит маршрут по host/path - чтобы понять, какой per-route конфиг фильтров применять. TLS / соединение (ClientTrafficPolicy) - это уровень L4: терминация TLS и лимиты соединения происходят на листенере, до того как HTTP Connection Manager начинает разбирать запрос, - этот шаг не конкурирует за порядок с HTTP-фильтрами ниже. Дальше идёт L7-цепочка HTTP-фильтров по порядку (CORS → extAuth → authN → расширения → rate limit), и терминальный router отправляет запрос в выбранный backendRefs. Обратите внимание: внешняя авторизация (extAuth) идёт до встроенных механизмов AuthN (API-key / Basic / OIDC / JWT) - в дефолтном порядке фильтров Envoy Gateway ext_authz стоит сразу после cors. Точная микро-очерёдность внутри каждого блока (например, между разными authN-механизмами или между Lua/ext-proc/Wasm) зависит от версии и настраивается через filterOrder - сверяйтесь с docs при тонкой настройке.
