# Envoy Gateway и Gateway API - представление и правки

Как связаны CRD Gateway API и Envoy Gateway, каким путём идёт запрос, где применяется каждая
политика и как выбрать режим развёртывания. Читатель уходит с понимания, **какое поле на что
влияет** - клик по узлу раскрывает назначение, связи и живой пример манифеста.

Опубликован: https://envoy-gateway-guide.onrender.com/ - **URL зарезервирован, деплоя ещё не было** (сервис `envoy-gateway-guide` в `../render.yaml`)
· Запуск: `python3 -m http.server` в этой папке → `http://localhost:8000`.

**Http-сервер обязателен**: слои подгружаются через `fetch`, а он блокируется на `file://`
политикой CORS - при открытии файла напрямую доска останется пустой.

Этот документ - про **представление** (что из чего состоит, где что менять). Визуальный
язык - в [`DESIGN.md`](DESIGN.md) и [корневом `DESIGN.md`](../DESIGN.md); процесс и
чек-листы - в [`CONTRIBUTING.md`](../CONTRIBUTING.md).

## Файлы и зона ответственности

| Файл | Что содержит | Когда править |
|------|--------------|---------------|
| `index.html` | **Оболочка**: header, табы слоёв, легенда, правая панель, футер + bootstrap-скрипт. Пустой `.board#board`, в который подгружаются слои. Разметки схем тут больше нет. | Изменить шапку/табы/легенду/футер; поменять порядок или список слоёв (массив `LAYERS` в bootstrap). |
| `layers/<name>.html` | **Разметка одного слоя** (`crd`, `traffic`, `policies`, `deploy`): `<div class="layer-panel" id="panel-<name>">` целиком - `<svg>`-схема (узлы/рёбра) или HTML-панель. Фрагмент без `<html>`/`<body>`. | Добавить/сдвинуть узел или ребро на схеме; изменить статичный текст внутри слоя. **Правьте только нужный слой - остальные не трогаются.** |
| `data.js` | **Контент-модель**: `PANELS` (панель на узел), `STEPS` (шаги трафика), `TRAFFIC_EDGES`. Чистые данные. | Изменить текст панели, поля манифеста, описания, шаги. **Большинство правок - здесь.** |
| `app.js` | **Поведение**: табы, выбор узла, вкладки Обзор/Манифест, клик по полям YAML, степпер. | Менять логику взаимодействия (редко). |
| `styles.css` | **Стиль**: токены темы «Blueprint Journal» + компоненты (см. `DESIGN.md`). | Цвета, отступы, типографика. |

**Порядок загрузки** (bootstrap внизу `index.html`): `data.js` (синхронно, data-глобали) →
`fetch` всех `layers/*.html` параллельно, инъекция в `#board` в порядке массива `LAYERS` →
**затем** динамически подгружается `app.js`. Ключевой инвариант: `app.js` вешает обработчики
при загрузке и стартует **после** того, как вся разметка слоёв уже в DOM, - поэтому `app.js`
не знает про асинхронность и не требует правок при добавлении слоёв. Если `fetch` слоя упал
(обычно - открыли по `file://`), доска показывает сообщение об ошибке, а `app.js` не грузится.

## Навигация

Четыре слоя, каждый - отдельный файл `layers/<name>.html`; при загрузке все инъектятся в
общий `.board#board`, таб переключает `.layer-panel.active`. Три слоя - свой
`<svg class="diagram">`; «Развёртывание» - HTML-панель.

| Слой | `data-layer` / panel id | Что показывает | Особое поведение |
|------|-------------------------|----------------|------------------|
| Ресурсы | `crd` / `#panel-crd` | Граф CRD, рёбра = поля-ссылки (`parentRefs`…). `controllerName` = точечное «владеет» (`.edge.config.owns`). | - |
| Трафик | `traffic` / `#panel-traffic` | Путь пакета client→backend + обратный ход (ответ) + xDS-поток. | Степпер 0→4 (прямой, emerald) + шаг 5 «Ответ» (обратный, amber); маркер `TLS terminate` (`#tls-marker`) с шага 2. |
| Политики | `policies` / `#panel-policies` | Спина пути + карточки политик + **упорядоченная цепочка фильтров** (`.chain`). | `.edge.attach` = привязка; `.cp-toggle` раскрывает control-plane полосу (`.cp-band`, viewBox); клик по `.chain-step[data-owner]` → открыть политику. |
| Развёртывание | `deploy` / `#panel-deploy` | Три режима (**Gateway per Service** / **Merged Gateways** / **ListenerSet**) + миграция Ingress→Gateway API. HTML-панель, без SVG-узлов. | Переключатель `.dp-mode` (стоит **под** диаграммой) меняет `data-mode` сразу у двух блоков: `#dp-topo` (топология 3 стека ↔ 1 общий + счётчики Envoy/LB/IP) и `#dp-compare` (показывается **одна** карточка описания режима - CSS по `[data-mode]`). Логика - блок «Deployment layer» в `app.js`. |

## Ключевой контракт

**`data-node` ↔ `PANELS`.** Каждый кликабельный узел схемы - это
`<g class="node" data-node="ID">`. При клике `app.js` берёт `PANELS[ID]` и рисует правую
панель. **`data-node` в разметке обязан совпадать с ключом в `PANELS`** - иначе клик открывает
пустую панель, и заметно это только если кликнуть именно этот узел.

Полей у панели нет в HTML - весь текст в `data.js`. Разметка держит только геометрию и подписи
внутри узла (`node-kind` / `node-title` / `node-sub`).

Псевдонимы: несколько узлов могут показывать одну панель - так сделано для слоя политик,
чтобы не дублировать контент:

```js
PANELS['p-envoyproxy']      = PANELS.envoyproxy;
PANELS['p-envoypatchpolicy']= PANELS.envoypatchpolicy;
PANELS['p-backendcrd']      = PANELS.backend;
```

**Второй контракт: `data-f` ↔ `manifest.fields`.** Ключ, обёрнутый в YAML как
`<span class="yk" data-f="КЛЮЧ">`, обязан существовать в `manifest.fields`. Рассинхрон -
клик по подчёркнутому полю ничего не раскрывает.

**Классы узлов и рёбер** (визуальная семантика, см. `DESIGN.md`):

Узлы (`<g class="node ...">`):
- `control` - control-plane узел (пунктирная рамка, «не трафик»).
- `dp` + `data-step="N"` - узел data-plane для степпера трафика (подсветка по шагам).

Рёбра (`<g class="edge ...">`):
- (без модификатора) - обычная ссылка/путь.
- `config` - control-plane/xDS (серый пунктир, «не запрос»).
- `attach` - привязка политики (синий пунктир, `targetRef`/`backendRefs`).
- `data` + `id="tN"` - сегмент пути трафика (участвует в степпере).

> Пунктир осознанно используется для «потока конфигурации / привязки», а не для трафика -
> это объяснено в легендах под схемами.

## Сквозные фичи

- **Легенда цветов** (`.color-key`, над `.stage` в `index.html`) - соответствие
  «цвет → роль ресурса».
- **Deep-link**: URL-хеш `#<layer>/<node>` (напр. `#policies/securitypolicy`) восстанавливает
  слой + узел; `app.js` пишет хеш при кликах (`writeHash` / `applyHash`).
- **Переход между слоями** (`data-goto="<layer>"`): любой элемент с этим атрибутом при клике
  переключает на указанный слой (делегированный обработчик в `app.js`). Используется чипом
  политик у HTTPRoute на слое «Ресурсы» (`.policy-hint`) - показывает, что к HTTPRoute
  крепятся `*Policy`, и уводит на слой «Политики» за деталями. Сами карточки политик туда не
  дублируются - лимит наглядности важнее полноты.
- **Опциональные ресурсы**: узел с `rect.node-box.opt` (пунктир + тег «опц.») - ресурс, без
  которого можно обойтись (напр. `ListenerSet`).
- **Failure-состояния**: опциональное `manifest.fields[k].failure` → amber-блок «Если сломать»
  в детали поля (`app.js`, `.fd-fail`).
- **Адаптив**: широкие `<svg>` обёрнуты в `.diagram-scroll` (горизонтальный скролл на узких
  экранах); media-queries в `styles.css`.
- **Правая панель по слоям**: `switchLayer` пишет `.wrap[data-layer]`, CSS реагирует. На
  `deploy` панель скрыта (`.side{display:none}`), но колонка `.stage` **не** перестраивается -
  ширина `.board` одинаковая на всех слоях, чтобы переключение табов не дёргало вёрстку.
  Легенда цветов там тоже скрыта (она про SVG-узлы).
- **Кэш-бастинг**: ассеты подключены с `?v=N`. Версия задаётся в трёх местах `index.html`:
  `<link>` на `styles.css`, литерал у `data.js` и константа `V` в bootstrap (ей версионируются
  `app.js` и `layers/*.html`). **Держите все три синхронными** - иначе часть читателей получит
  старый CSS с новым HTML. Точные места - `grep -n '?v=' index.html`.
- **OG-теги и favicon**: в `<head>`, абсолютными URL на `envoy-gateway-guide.onrender.com`.
  Превью - `og-preview.png` 1200×627. **При смене домена** обновить `og:url` и `og:image` и
  заново прогнать Post Inspector: превью кешируется по URL надолго.

## Как выполнить типовые правки

### Изменить текст/поля панели узла

Только `data.js` → `PANELS[ID]`. Форма записи задокументирована в шапке `data.js`. Кратко:

- `lead` - вводный абзац; `note` - жёлтый callout.
- `fields` - строки характеристик. **Показываются только у узлов без манифеста** (физические
  элементы пути) под заголовком «Характеристики». У CRD с манифестом они скрыты - их роль
  выполняет вкладка «Манифест», иначе дублирование.
- `refs` - «Связи». Кортеж `[dir, verb, target, via]`, рисуется как направленное ребро
  **источник → цель** с подсветкой текущего узла: `dir:'out'` → текущий узел источник
  (`этот → target`), `dir:'in'` → текущий узел цель (`target → этот`). `verb` должен читаться
  активно со стороны источника (у Controller `out` «управляет» GatewayClass; у GatewayClass
  `in` «владеет» Controller). `via` - поле-связь, показывается mono-чипом под ребром.

### Добавить/изменить интерактивный манифест

В `PANELS[ID].manifest`:

1. `yaml` - строка манифеста. Ключевое поле оборачивается
   `<span class="yk" data-f="КЛЮЧ">имя_поля</span>`, значения - `<span class="v">…</span>`.
2. `fields.КЛЮЧ = { purpose, links[], impact }` - блок под манифестом
   (Назначение / Связи / Влияние). `data-f` в YAML обязан совпадать с ключом в `fields`.

Если `manifest` нет - вкладка «Манифест» автоматически отключается (узел «физический», а не CRD).

### Добавить новый узел на схему

1. `data.js`: добавить `PANELS['newid'] = {...}`.
2. `layers/<name>.html`: в `<svg>` нужного слоя добавить
   `<g class="node" data-node="newid" tabindex="0" role="button" aria-label="...">` с
   `rect.node-box` (+ опц. `rect.glow-ring`) и `text`-подписями.
3. `app.js` менять не нужно - обработчики вешаются на все `.node` при загрузке.

Лимит наглядности: ≤7-9 узлов в поле зрения.

### Добавить новый слой

1. Создать `layers/<name>.html` с
   `<div class="layer-panel" id="panel-<name>" role="tabpanel">…</div>` (фрагмент, без `<html>`).
2. `index.html`: добавить кнопку `.tab[data-layer="<name>"]` в `.tabs` и вписать `<name>` в
   массив `LAYERS` bootstrap-скрипта (порядок в массиве = порядок в доске).
3. Зарегистрировать слой в `app.js` → объект `layerPanels`
   (`<name>: document.getElementById('panel-<name>')`).

### Изменить шаги слоя «Трафик»

Только `data.js`:

- `STEPS[0]` - обзор; `STEPS[n]` - шаг n (`done[]` = зелёные узлы,
  `current{edge,node}` = синий активный сегмент, `caption`).
- `dir` на шаге: `'fwd'` (прямой, emerald) или `'rev'` (ответ, amber - подсвечивает все рёбра
  назад). `tls:true` - пульсирует маркер TLS-терминации.
- `TRAFFIC_EDGES` - id рёбер по порядку пути; используется для «пройденных» рёбер и обратного хода.
- Длина прямого пути = число шагов с `dir!=='rev'` (в `app.js` считается автоматически как
  `FWD_TOTAL`); прогресс и счётчик считаются от неё.
- Добавляете шаг - добавьте кнопку `.step-dot[data-step="N"]` в `layers/traffic.html` (степпер
  живёт внутри слоя) и, при необходимости, ребро `data-step` / id в `TRAFFIC_EDGES`.

## Проверка после правок

1. `python3 -m http.server` → открыть в браузере (или Playwright по `http://localhost:PORT`).
2. Консоль чистая (единственное допустимое - `favicon.ico 404`). Доска не пустая - четыре
   `.layer-panel` подгрузились. Если пусто и в консоли ошибка `fetch` - открыли по `file://`
   вместо http-сервера.
3. Прогнать: переключение четырёх табов; клик по узлу → панель; Обзор/Манифест; клик по
   подчёркнутому полю → блок деталей (+ amber «Если сломать» где есть), повторный клик
   сворачивает; степпер 0→4 + шаг 5 «Ответ» + прогресс-бар; TLS-маркер с шага 2; кнопка
   control plane в слое политик; клик по шагу цепочки фильтров → открыть политику; слой
   «Развёртывание» - переключатель под диаграммой меняет и топологию со счётчиками
   Envoy/LB/IP, и карточку описания режима (видна ровно одна), у Merged внутри карточки
   сниппет `mergeGateways: true`; deep-link (`#deploy`, `#policies/securitypolicy` при
   загрузке); Esc закрывает панель; Tab/Enter по узлам.
4. Нет переполнения текста за границы `<text>` (замер `getComputedTextLength()`) и нет
   горизонтального скролла страницы на 1360 и 390px.
5. `node ../tools/check-tokens.mjs envoy-gateway-visualization` из корня репы - без расхождений.
6. При правке CSS/JS/слоёв - бампнуть версию: константа `V` в bootstrap `index.html` и
   `?v=N` у `styles.css` в `<head>`.

Общий чек-лист перед публикацией - в [`CONTRIBUTING.md`](../CONTRIBUTING.md) §6.

## Отклонения и открытые вопросы

**Отклонения от общего закона** - в [`DESIGN.md`](DESIGN.md) §5. Кратко: семантическая роль
«потеря/отказ» не введена, rose свободна и занята брендовым штрихом.

**Открытые вопросы:**

- **Self-test отсутствует.** Гайд не отвечает на `?selftest=1`, хотя это требование
  `CONTRIBUTING.md` §5. Контракты `data-node` ↔ `PANELS` и `data-f` ↔ `manifest.fields`
  сейчас проверяются только руками, а рассинхрон не виден, пока не кликнешь именно тот узел.
  Это главный технический долг гайда.
- **Post Inspector не прогнан.** OG-теги и favicon на месте, но превью LinkedIn кешируется
  по URL надолго, поэтому урл нельзя светить нигде (пост, чат, инспектор) до того, как
  `https://envoy-gateway-guide.onrender.com/` реально отдаёт страницу и картинку. См. `TODO.md`.
- **Слой «Развёртывание» без SVG-узлов**, поэтому на нём не работают ни легенда, ни панель
  деталей, ни диплинк на элемент. Осознанно: материал там сравнительный, а не структурный.
- **Язык надзаголовка.** `.eyebrow` начинается с англоязычного `Reference` при `lang="ru"` -
  решение осознанное (смешанная аудитория LinkedIn), но при смене аудитории пересмотреть.
